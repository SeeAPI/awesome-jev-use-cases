# 证据能说明什么

[English](evidence.md) · [简体中文](evidence.zh-CN.md)

有参考价值的实现不一定经过效果验证。我们分别记录核查内容和作者主张。证据只适用于相应任务：文本测试不能证明原生图像理解能力。

| 标签 | 所需证据 | 不能证明 |
| --- | --- | --- |
| `source-reviewed` | 明确的公开来源和核查日期 | 已检查代码或运行项目 |
| `docs-reviewed` | 说明接入方式及判断流程的文档 | 运行正确性或独立测得的准确率 |
| `author-demo` | 注明作者和边界的演示 | 独立复现或生产可用性 |
| `seeapi-tested` | SeeAPI 运行报告，包含输入、配置、返回模型和失败记录 | 超出本次运行范围的通用准确率 |
| `independently-benchmarked` | 公开数据集、方法、原始结果和可复现流程的独立评估 | 在无关任务上的表现 |

这些是证据类型，不是通用的质量排名。对于代码层面的问题，作者视频并不一定比清楚的实现文档更有价值。先看任务匹配，再比较相关、可复现的证据；不要只按 Star 数推荐。

最初整理的 12 条结构化记录沿用了仓库已有的文档核查。本次结构调整没有新增 SeeAPI 实测标记。其他案例在元数据核查前保留原文中的限制说明。只阅读了作者评测文档的项目，仍属于 `docs-reviewed`。

升级为实测需要报告路径，独立基准还需要数据集路径。报告应区分人工标签、合成样例、作者测量和独立运行。未知内容应注明未知，不补造数值。保留请求和返回的模型标识、日期、输入及策略版本、排除项、失败记录和采样条件。
